Apache Shiro is a top-level project of the https://www.apache.org/[Apache Software Foundation] (ASF) and is governed under the https://www.apache.org/foundation/governance/[ASF governance model].

== Project members

The current members of the project, including the committers and the Project Management Committee (PMC), are listed by the ASF:

* https://projects.apache.org/committee.html?shiro[Apache Shiro PMC and committers]
* https://people.apache.org/committers-by-project.html#shiro[Committers by project]

Only committers have write access to the source repository and other sensitive project resources (release signing, the website, the security mailing list).
The PMC members additionally vote on releases and on adding new committers and PMC members.

== Roles and responsibilities

[cols="1,3",options="header"]
|===
| Role | Responsibilities

| User
| Uses Shiro. Asks questions and gives feedback on the link:mailing-lists.html[mailing lists] and in https://github.com/apache/shiro/discussions[GitHub Discussions].

| Contributor
| Reports defects and submits pull requests, following the https://github.com/apache/shiro/blob/main/CONTRIBUTING.md[contributing guide]. Contributors either have an https://www.apache.org/licenses/icla.pdf[ICLA] on file with the ASF or tick the license acknowledgment checkbox in the pull request template.

| Committer
| Has write access. Reviews and merges contributions, triages issues, takes part in discussions, and may act as release manager.

| PMC member
| A committer who also takes part in project governance: votes on releases, new committers and PMC members, handles private reports sent to the security team, and is responsible to the ASF board for the health of the project.

| PMC chair
| Officer of the ASF who reports on the project's status to the ASF board, and is the administrative contact for the project.
|===

== Granting access

New committers are proposed by an existing committer and elected by a PMC vote.
Before elevated access is granted, the PMC reviews the candidate's sustained, public contributions, communication on the project's lists, and willingness to follow the https://www.apache.org/foundation/policies/conduct.html[ASF Code of Conduct].
New committers must file an https://www.apache.org/licenses/icla.pdf[ICLA] with the ASF.
Access to sensitive resources is limited to committers and removed when a committer becomes inactive or leaves the project.
See also https://www.apache.org/dev/new-committers-guide.html[the ASF new committer guide] and the https://www.apache.org/foundation/how-it-works.html[ASF "How it works" documentation].

== Decision making

Decisions are made on the public `dev` mailing list by consensus, following the https://www.apache.org/foundation/voting.html[ASF voting process]. Releases require a PMC vote.
